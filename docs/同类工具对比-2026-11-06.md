# 同类 AI 渗透工具深度对比与融合清单（2026-11-06）

> 触发：用户反馈「这两天任务几乎不调 skill」+ 要求分析 14 个同类项目的可取部分。
> 本文分两部分：① skill 调用率根因分析（数据实证）；② 14 项目逐项结论（采纳/跳过）。

## 一、Skill 调用率为什么低（数据实证）

**数据**（Kali artex 库，2026-11-06）：
- `skill_usage` 全生命周期 **8 次**（vuln-hunting 6 / api-recon 1 / redteam-ops 1）；
- 任务 18（Vue 站点，跑了一天）：**0 次 Skill 调用**；
- 近三天工具分布 top25 里 **没有 Skill**：Bash 25.7k、list_facts 4.5k、node_detail 3.5k……
- 21 个 skill 的默认绑定 **v0.4.56（11-05）才种上**——之前 15/16/17/18 大部分时间工具面里就没有。

**三层根因**：
1. **结构性（已修）**：绑定缺失 → 可用技能列表几乎是空的；
2. **行为性（本次修）**：Skill 是**元工具**——模型只在工具描述尾部看到可用技能，
   系统提示里**一个字都没提**。DeepSeek-flash 级模型不会主动调可选元工具。
   这与当年宿主工具「装了没人用」是同一病根（worker.go 注释里记录过），
   当时的解法是「工具清单进 system prompt」，技能必须同款处理。
3. **路由性（可观测）**：意图文本与技能无关联，没有机制提示「这条意图该先看哪个技能」。

**修复（v0.4.60）**：`renderSystem` 统一注入「技能速查块」——按 agent 绑定生成
`- skill名：何时用` 清单 + 调用方式说明，覆盖 worker/planner/pentest/chat 全部
agent；registry 60s 缓存。回归测试验证绑定项进块、无绑定不加块。

|---|---|---|---|

### 本批实施清单（v0.4.60）

1. ✅ **技能速查注入 system prompt**（根因修复，见 §一）
2. ✅ **内置 4 个任务 Playbook**（PentestAgent 思路；安康系列验证过的目标结构）
3. ✅ **独立复现规划规则**（Pentest-AI / Swarm 思路）
4. ✅ **HexStrike MCP 预设**（150+ 工具桥）
5. ⏭ 后续候选：Metasploit RPC 桥（PentAGI 思路，成本较高，先观察 HexStrike 接入效果）

### 明确不做

- Neo4j 图数据库（双图已覆盖语义，引入重依赖不值得）；
- tmux 持久会话沙箱（平台已有 hostd + 工具链，收益低）；
- 引入 LangGraph/多框架编排（我们的 planner/worker 编排已验证，不换底座）。
