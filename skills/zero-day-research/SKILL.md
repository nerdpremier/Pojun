# 0day 研究路径（授权范围内）

## 研究循环

```
观察异常 → 形成假设 → 最小验证 → 判影响面 → 记录/再迭代
```

- 每条假设写成一句话（「参数 X 未校验长度 → 堆溢出 → 崩溃」），验证后判真假；
- 失败也写 fact（假设、方法、结果），避免重复研究。

## 补丁差分（最快出洞路径）

1. 找到旧版/新版二进制或源码（官网历史版本、Docker 镜像层、发行版补丁）；
2. 比对：
   - 源码：`git log --oneline v1.0..v1.1`、`git diff v1.0 v1.1 -- <关键目录>`；
   - 二进制：`bindiff`/`radiff2 -C`、函数签名与字符串差异；
3. 看补丁改了什么校验（边界/权限/签名）→ 反向构造未校验输入；
4. 本地起旧版验证崩溃/绕过，再在授权目标上做最小验证。

## 行为异常线索

- 错误信息泄露内部路径/参数名（说明后端直接拼接）；
- 同一参数不同编码返回不同结果（解析差异）；
- 状态机跳步（跳过验证步骤仍成功）；
- 时间差（越界/大对象处理慢）；
- 响应长度差异（截断/吞字节 → 解析器边界问题）。

## Fuzz 最小化

- 抓真实请求为种子（HTTP/协议/文件格式）；
- 轻量优先：`ffuf -w payloads.txt -u <url> -mc 500 -fs <正常长度>` 先筛异常；
- 崩溃/异常样本立即保存（`save_evidence`）并记录环境；
- 不跑大并发（生产目标要求最小请求数），单线程小字典足够定位方向。

## 影响面判定

- 能崩 → 可能 DoS（低价值，谨慎）；
- 能读越界数据/绕过鉴权 → 高危；
- 能执行代码 → critical；
- 无法证明影响的异常 → 只写研究 fact，不报漏洞。

## 报告口径

- 0day 类发现附：触发条件、最小 PoC、受影响版本、根因分析（代码/反汇编片段）；
- 明确「未在真实业务数据上扩大验证」的边界；
- 复现步骤要让第三方能独立验证。
