# 行动安全（OPSEC）速查

## 核心原则

- **每个动作都要能解释来源**：授权范围内的测试流量也要尽量低噪，避免误伤业务；
- 一旦被 WAF/EDR/封禁拦下，先停手分析，不要换 IP 硬打（会扩大暴露面）。

## 身份与基础设施

- 不混用身份：不同任务/不同目标用不同出口与 UA；
- 平台已提供出口代理池（proxypool）与 MITM 留痕代理——测试流量走它们即可；
- 不自建公网 C2、不在目标上留可信长期后门（授权演练另有规则时从其规则）。

## 流量节奏

- 探测小步走：单请求→小组→批量；批量前先确认不会触发风控；
- 对登录/短信/支付类接口限速（≥2s/请求），不并发；
- 大字典爆破只在授权且明确允许时使用，先查锁定策略。

## 痕迹与日志

- 上传的工具/脚本记路径，任务结束前清理（授权范围内）；
- 不在目标写明文标记；必要标记用无害、可解释的文件名；
- 所有动作有流量/命令记录（平台自动留痕），报告只引用真实记录。

## 报警与中止

- 发现目标告警/验证码升级/连接被阻断 → 记录现象，暂停该类请求，换方向；
- 被蓝队响应（封禁/蜜罐）→ 写 fact 并上报给操作者，不自行对抗；
- 蜜罐识别：过于顺利的路径、异常开放的服务、与业务不符的数据 → 先验证再深入。
